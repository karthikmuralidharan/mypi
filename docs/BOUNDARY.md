# The config / data boundary

This repo tracks **configuration and authored work**. It deliberately does not
track **data**. This document records where that line sits and why, so the
decision does not have to be re-derived later.

## Tracked

| Path | What it is | Why tracked |
| --- | --- | --- |
| `config/settings.json` | Provider, default model, thinking level, theme, `packages[]`, `enabledModels[]`, skill toggles | The single most valuable file. `packages[]` is the manifest that regenerates every plugin, skill, and agent. |
| `config/mcp.json` | MCP server registrations | Hand-maintained. |
| `config/AGENTS.md` | Global agent instructions | Hand-maintained (currently a compound-plugin block). |
| `config/npm/package*.json` | Exact pinned versions of all 26 pi extensions | `package-lock.json` makes the extension set byte-reproducible. |
| `config/extensions/` | Config files *for* installed extensions (aperture, pi-rtk-optimizer) | Settings, not code. Not regenerable — onboarding state and gateway URL live here. |
| `extensions/` | Extensions I write myself | Authored work. Currently empty; see below. |
| `skills/` | The 7 skills I authored | Authored work, exists nowhere else. |
| `manifests/my-skills.txt` | Allowlist separating my skills from plugin skills | Single source of truth for both scripts. |
| `manifests/agents-skill-lock.json` | Provenance for 6 third-party skills in `~/.agents/skills/` | Each entry has a `sourceUrl`, so `bootstrap.sh` can re-clone them. |

## Not tracked, and why

### Data — excluded for now, by choice

- `pi-hermes-memory/{MEMORY.md,USER.md,failures.md}` — hand-curated global memory (~18KB).
- `projects-memory/*/MEMORY.md` — per-project memory, includes work context.
- `pi-hermes-memory/sessions.db` — 1.6 GB.
- `sessions/` — 167 MB of transcripts.

This is the one judgement call worth revisiting. The global memory files are
genuinely irreplaceable and small. They are excluded today because memory is
data with a different lifecycle than config: it changes on almost every
session, it contains work context, and it wants append-only backup rather than
diff review. If that changes, add a `memory/` directory and drop the
corresponding `.gitignore` line — nothing else needs to move.

### Regenerable — no value in versioning

`npm/node_modules/` (626 MB), `models-store.json`, `mcp-cache.json`,
`run-history.jsonl`, `cache/`, `~/.pi/models/` (154 MB of Whisper weights),
`~/.pi/workflows/runs/`, `~/.pi/context-mode/`.

### Plugin-installed — restored from a manifest instead

36 `ce-*` skills, `lfg`, and all 67 `agents/*.md` are generated by the
compound-engineering plugin, which is itself pinned in `settings.json`
`packages[]`. Verified: every file in `agents/` is either plugin-managed
(`compound-engineering/install-manifest.json`) or rpiv-managed
(`agents/.rpiv-managed.json`). Nothing there is hand-written. Versioning ~3 MB
of it would add a noisy diff on every plugin update and buy nothing.

Trade-off accepted: if an upstream package is yanked, that content is not
byte-recoverable. `config/npm/package-lock.json` mitigates this for npm
packages by pinning exact versions.

### Machine-specific — would be wrong on another machine

- `auth.json` — credentials. Never version.
- `trust.json` — absolute paths to local repos; pi re-prompts anyway.
- `~/.pi/remote/peers.json` — collab peer state.

### Tool-managed — regenerated by reinstalling the tool

`extensions/herdr-agent-state.ts` self-identifies as
`// installed by herdr; reinstalling or updating the integration overwrites
this file.` Versioning it would create phantom diffs every time herdr updates.
It is the reason `extensions/` is currently empty: there are no hand-written
extensions yet.

## Keeping it honest

`sync.sh` pulls live config into the repo. It only copies from the paths in the
tracked table above, uses `manifests/my-skills.txt` as an allowlist, and skips
any extension file whose first three lines say `installed by` or `managed by`.
It cannot pick up data or secrets by accident.
